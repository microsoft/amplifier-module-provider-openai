feat(config)!: rename max_tokens/filtered; add extra_request_params

Renames (back-compat alias + one-shot deprecation warning via the new
`_read_renamed_config()` helper -- new key always wins when both are set,
warns once naming both names):

- max_tokens -> max_output_tokens (self.max_tokens -> self.max_output_tokens).
  The per-call KWARG `max_tokens` is NOT renamed -- it is a caller-facing
  contract shared with other providers and the kernel; only the config key
  changes.
- filtered -> hide_dated_models (self.filtered -> self.hide_dated_models).
  `_parse_config_bool` still applies after rename resolution.

`_DEPRECATED_ALIAS_CONFIG_KEYS = {"max_tokens", "filtered"}` keeps both old
names in `_KNOWN_CONFIG_KEYS` so they never ALSO trigger the generic
unknown-key sweep on top of their own targeted deprecation warning.

New: `extra_request_params` (dict[str, Any], settings-only, never a
ConfigField) -- the documented escape hatch for Responses API parameters
this provider does not model, including `store` (otherwise managed
automatically). Validated at mount (must be a mapping); merged into
`params` LAST via `_merge_extra_request_params()`, on both the primary
request (right before the llm:request event emission, so the emitted
`raw` payload reflects what is actually sent) and the incomplete-
continuation request. Clobbered provider-computed keys are warned once
per key per provider instance, naming every clobbered key sorted.

New tests:
- tests/test_config_renames.py -- both renames' new/old/both/neither
  matrix, the "old key never double-warns" guard, and the
  _DEPRECATED_ALIAS_CONFIG_KEYS bookkeeping.
- tests/test_extra_request_params.py -- invalid-type rejection, no-op on
  absent/empty, novel-key passthrough, single/multi-key collision
  (sorted, warns once, never repeats), store override including
  overriding background mode's forced True, and the continuation
  regression guard (extras + instructions both survive continuation).
