Behavior and documentation payload for parent
1. ModelCapabilities.context_window is the total window. GPT-5.6 alias and its
   Sol/Terra/Luna IDs plus the five exact GPT-6 IDs have total 1,050,000,
   independent max input 922,000, and max output 128,000. Request input allowance
   is min(total minus output reserve, independent input ceiling, optional
   standard-price input threshold) minus 4,096. At max output this is 267,904
   Standard or 917,904 with long context enabled. Host compaction metadata still
   reports the selected safe input/price cap, not the preflight allowance.
2. GPT-5.2 and Pro use 400,000 total context and omit injected effort by default.
   GPT-5.4 Mini uses 400,000 total and 272,000 max input without a long-price
   threshold. GPT-5.5 and Pro use 1,050,000 total and a 272,000 pricing threshold.
   The current pricing table explicitly gives Pro long rates too; an early
   tentative no-threshold interpretation was rejected against that source.
3. Exact GPT-5.6 and GPT-6 IDs accept prompt_cache_options.ttl 30m or 12h.
   Legacy prompt_cache_retention is removed for those final models. Effort and
   TTL validation runs after final model overrides. Cost needs explicit raw
   input/output/cache counts and non-overlapping lifetime usage buckets for
   writes; missing, malformed or inconsistent evidence stays unknown. Requested
   TTL is not billing evidence. Historical GPT-5.6 snapshot pricing requires the
   same usage evidence without inheriting new-feature eligibility.
4. Pricing now includes documented legacy models and GPT-5.4/5.5 Standard/long
   rates, explicit 12h write rates for modern models, and the GPT-5.6 Sol alias.
   Numerical tests preserve whole-request rerating, the strict >272K boundary,
   non-overlapping cache accounting and unknown costs. Existing service-tier
   scope is preserved, not generalized from public model names.
5. Direct OpenAI discovery excludes only documented/reported known shutdowns.
   Optional valid shutdown_date is carried in ModelInfo.defaults as inert
   metadata because Core has no lifecycle field. Explicit pins warn but are not
   replaced or blocked. Azure/custom catalogs and deployment aliases are not
   classified by OpenAI shutdown rules. Retired direct-OpenAI deep-research IDs
   no longer automatically select stored background work; explicit background
   and generic background polling remain. Compatible endpoints keep the old
   model-identity behavior.
6. Image auto selection uses the newest documented full/Sunburst alias actually
   in the selected account catalog. It does not switch to Flare/mini or invent
   future models. A mini-only/Flare-only catalog now errors; explicit tier and
   snapshot pins remain unchanged. GPT Image 2.6 Flare/Sunburst are supported for
   Images API generation/edit only. Their Responses-tool combination remains
   unqualified and is rejected before dispatch. Catalog visibility is not
   generation entitlement. Existing legacy image pins remain supported by the
   adapter; this is not a claim that retired models work at api.openai.com.
