feat(config)!: remove 5 config keys with targeted migration warnings

Removed entirely (config key + attribute + ConfigField, where applicable):

- enable_response_chaining -- the chaining code path is gone (commit 1)
- enable_state -- store is now always false, or true internally for
  background mode; extra_request_params is the escape hatch (added in a
  follow-up commit)
- enable_reasoning_context -- reasoning.context is forwarded ungated via
  the legacy `reasoning` dict now (commit 1's A18); the flag gate it used
  to control no longer exists
- thinking_budget_tokens, thinking_budget_buffer -- the budget arithmetic
  in the extended_thinking block is removed. extended_thinking still
  forces reasoning.effort="high" when no reasoning dict is already set
  (PRESERVED -- azure's test depends on this); it just no longer adjusts
  max_output_tokens. Set max_output_tokens directly for a larger budget.
  Also removed the now-dead `thinking_enabled`/`thinking_budget` fields
  from the llm:request event payload (zero consumers verified).

Migration mechanism: `_INERT_CONFIG_KEY_MESSAGES` replaces the old
single-key `effort`-only inert-key loop with a table of five removed keys
plus the pre-existing `effort` entry, each with a targeted one-line
message naming what changed and what to do instead. Every message fires
from ONE loop in `__init__`, and every one of these keys stays in
`_KNOWN_CONFIG_KEYS` (via `_RECOGNIZED_INERT_CONFIG_KEYS`) so it can never
also trigger the generic "Unrecognized config key" sweep -- a key must
never produce two warnings.

`_CONSUMED_CONFIG_KEYS` drops from 32 to 27 entries.

New tests: tests/test_config_migration_warnings.py -- each removed key
warns exactly once with its targeted message, never double-warns via the
unknown-key sweep, the `effort` KEEP still fires with its original
meaning, and all five together produce exactly five warnings.

Test delta: dropped enable_state/enable_reasoning_context from
test_config_bool_parsing.py's per-key coercion matrix (both attributes are
gone); updated the _CONSUMED_CONFIG_KEYS count assertion in
test_model_aware_config_gating.py (32 -> 27); rewrote
test_extended_thinking_enables_reasoning_and_budget_adjustment (renamed to
test_extended_thinking_forces_high_effort_without_budget_arithmetic) to
assert the effort-forcing behavior without the removed budget arithmetic.
